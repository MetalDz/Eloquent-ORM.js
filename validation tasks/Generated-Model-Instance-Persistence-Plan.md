# Generated Model Instance Persistence Plan

Last updated: 2026-03-12  
Status: IN PROGRESS

## Goal
- Prove that models generated by `make:model` inherit the new instance persistence API.
- Verify runtime support for:
  - `fill()`
  - `save()`
  - `patch()`
- Keep the proof on generated application model files, not hand-written stand-ins.

## Scope
- SQL app model generated by `make:model`
- Mongo app model generated by `make:model --mongo`
- Template update for `src/cli/templates/model.tpl` so generated files advertise the new API

## What Must Be Verified
- Generated SQL model instances expose `fill()`, `save()`, and `patch()`.
- Generated Mongo model instances expose `fill()`, `save()`, and `patch()`.
- Generated SQL models persist through bound SQL adapter calls.
- Generated Mongo models persist through native Mongo `insertOne` / `updateOne`.
- Generated files include instance persistence usage examples from the model template.

## Template Check
- `model.tpl` is the only template that needs an update for this slice.
- No other `.tpl` files define model runtime APIs.
- Scenario model generation is out of scope for this generator-specific check.

## Acceptance Criteria
- A focused CLI-facing runtime test generates app models and executes `fill().save().patch()`.
- The generated SQL model proves safe parameterized persistence.
- The generated Mongo model proves safe native document persistence.
- Generated files contain the new instance persistence comment block.
- Focused Jest run and `typecheck` both pass.
