# Scenario Generated Model Persistence Plan

Last updated: 2026-03-12  
Status: IN PROGRESS

## Goal
- Prove that models generated by `make:scenario` inherit `fill()`, `save()`, and `patch()`.
- Cover both SQL and Mongo scenario generation paths.
- Keep the check isolated from the normal app directories by generating into temp locations.

## Why This Slice Exists
- `make:model` uses `model.tpl`, which is already covered.
- `make:scenario` builds model files from inline code in `makeScenario.ts`.
- That inline generator must stay in parity with the model template for runtime API docs and inherited behavior.

## What Must Be Verified
- SQL scenario-generated `User` model exposes `fill()`, `save()`, and `patch()`.
- Mongo scenario-generated `User` model exposes `fill()`, `save()`, and `patch()`.
- SQL scenario-generated model persists through adapter-bound writes.
- Mongo scenario-generated model persists through native `insertOne` / `updateOne`.
- Generated scenario model files include the new instance persistence example block.

## Acceptance Criteria
- A focused test generates scenario models in temp directories.
- The generated SQL and Mongo `User` models run `fill().save().patch()` successfully.
- The inline generator in `makeScenario.ts` includes the instance persistence doc block.
- Focused Jest run and `typecheck` both pass.
