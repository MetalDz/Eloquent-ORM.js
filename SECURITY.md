# Security Policy

Last updated: 2026-03-17

## Supported Versions

| Version     | Supported |
|-------------|-----------|
| 1.0.x       | Yes       |
| 0.10.x      | Yes (maintenance only) |
| < 0.10.0    | No        |

## Security Scope

- Runtime and ORM internals under `src/core/*` and built `dist/*`.
- Database connection configuration paths and migration/seed execution flows under `src/config/*` and `src/cli/*`.
- Public package exports from `src/index.ts` (or `dist/index.js`).

Out of scope:

- Local environment and host configuration mistakes (open networks, weak DB users, leaked `.env` files).
- Vulnerabilities in third-party services (databases, drivers, or external dependencies) unless they are introduced by direct runtime configuration in this package.
- Application business logic and custom code generated by consumers.

## Reporting a Vulnerability

1. Do not open a public issue with exploit details.
2. Open a private advisory for this repository.
3. Include:
   - affected package version
   - impact and reproduction steps
   - minimal PoC (if available)
   - environment (`DB_CONNECTION`, runtime mode, OS)

## Response Process

- Initial triage target: 3 business days.
- Remediation target:
  - critical/high: next available patch
  - medium/low: scheduled patch/minor release
- Fix notes are published in release changelogs and docs release notes.

## Coordinated Disclosure

- Maintainers reserve time to reproduce, patch, and validate before public release.
- Public disclosure should follow after fix release or an official mitigation announcement.
